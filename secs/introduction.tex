\section{Introduction}

Distributed Asynchronous Object Storage (DAOS) is a high-performance, open-source parallel I/O stack built on Non-Volatile Memory Express (NVMe) and Remote Direct Memory Access (RDMA) technologies \cite{daos-exascale-storage2016sc, daos-intro2020, daos-dram-intro2023, daos-github}. It is designed to replace POSIX file and directory abstractions with a versioned, key-value object model. Since its initial deployment in 2020, prior studies have demonstrated DAOS's excellent scalability, showing it matches or outperforms traditional parallel file systems \cite{daos-vs-lustre2022pdsw, daos-arm2023SCAsia, daos-scalability2023SCAsia, daos-perf-explore2024scw, DAOS-aurora-20-node-test2024scw, XianheSun2023evaluation}. Motivated by its success in reducing I/O contention in weather-prediction workflows and machine-learning training pipelines \cite{hdf5-daos2022tpds, daos-adios2024ISC, hpc-weather2023ipdps, manubens2024reducing, daos-smartnic2025scw, devarajan2021dlio, mlperf-storage-github, brim2025dug-daos-aio}, we plan to use DAOS as a burst buffer for scientific streaming systems, where raw network packets stream from a large number of scientific instruments directly into high-performance computing (HPC) facilities and must be absorbed at line rate, without intermediate staging before reaching DAOS \cite{ejfat2022indis}.

Scientific streaming pipelines stress DAOS differently from the checkpoint- and training-style workloads of prior studies. Many instrument streams write in parallel, so throughput must hold under heavy intra-node concurrency and scale across client nodes. Line-rate absorption makes tail latency the binding constraint, since one slow write-back pressures the whole pipeline. The workflow spans write-dominated ingestion, mixed online analysis, and read-only post-processing. Raw detector events are small (approximately 1~MiB each), compared with those in checkpoint-based systems. Prior evaluations primarily focus on peak throughput, while we investigate tail latency, read/write patterns, and mixes in addition to throughput. We characterize DAOS across two representative DAOS deployments, including a 128-node system on Aurora \cite{aurora-intro2025}. Our key findings are summarized as follows:

\begin{itemize}
\item I/O request size relative to the DAOS chunk size is the first-order performance factor. Chunk-aligned requests saturate the NIC bandwidth with modest concurrency, whereas smaller requests remain IOPS- and CPU-bound.

\item At fixed total concurrency, the process/queue-depth split leaves throughput unchanged but can inflate P99.99 latency to 26$\times$ the median. More processes with shallower queues minimize tail latency.

\item DAOS scales near-linearly to multi-TiB/s across client nodes for large objects, but per-object overhead causes many-small-object reads to plateau at $3$--$5\times$ lower, motivating event aggregation before ingestion.
\end{itemize}
