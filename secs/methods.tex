\subsubsection{Aurora}
Aurora is Argonne National Laboratory's exascale supercomputer with over 10,000 compute nodes \cite{aurora-intro2025}. Aurora currently has the largest DAOS deployment in production, comprising 1,024 storage nodes \cite{aurora-daos-slingshot-rpc2025cug, io500-ics26}. We were allocated a 100~TB DAOS pool under the \textit{daos\_user} group. Per the Aurora user guide \cite{daos-aurora-guide} and our system queries, this group spans 128\footnote{Only 126--127 nodes were active during the experiments.} storage nodes, each with 16 PMem devices and 2 200Gbps Slingshot-11 Ethernet NICs.

The Aurora nodes are connected via a large-scale Dragonfly network \cite{aurora-intro2025, daos-aurora-guide}. The 1,024 DAOS server nodes in 64 racks are organized into 8 Dragonfly groups, and the compute/client nodes are divided into 166 groups. This topology allows for efficient communication between arbitrary client-server pairs but still introduces some latency and contention because of the multi-hop routing. This is the reason that bandwidth performance demonstrated in \cite{DAOS-aurora-20-node-test2024scw} are higher than what we observed in our experiments.


\subsubsection{Testbed}
We host a 3-node DAOS storage testbed locally. Unlike Aurora, the testbed uses DRAM as the first-tier storage and InfiniBand as the interconnect. A single DAOS client node accesses it via a 200~Gbps InfiniBand link. The server and client nodes are connected to the same InfiniBand switch, ensuring low-latency RDMA access.

\subsection{Benchmarking Methods}

\subsubsection{fio}

\textit{fio} (Flexible I/O Tester) is a widely used single-node storage benchmarking tool supports a broad range of I/O engines \cite{fio-github} and configurable memory access patterns. 

\textit{fio} achieves parallelism through 
configurable block sizes and queue depths . 


\subsubsection{ior}
ior is an MPI-native parallel I/O benchmark \cite{io500-design2019ics, ior-github}

IOR is an MPI-native parallel I/O benchmark designed to evaluate the performance of parallel file systems and storage systems at scale \cite{io500-design2019ics, ior-github}. It supports multiple I/O interfaces—including POSIX, MPI-IO, HDF5, and DAOS—enabling direct, apples-to-apples comparison of throughput across different access APIs on the same system.
